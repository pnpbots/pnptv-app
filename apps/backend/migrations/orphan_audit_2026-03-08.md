# PNPtv! Orphan & Incomplete Account Audit
**Date:** 2026-03-08
**Auditor:** DBA Agent (read-only — no deletes or updates executed)
**Database:** `pnptvbot` via `docker exec pg-pnptv psql -U pnptvbot -d pnptvbot`
**Total users audited:** 4,662 (excluding synthetic accounts: `SYSTEM`, `W1Jl2z3IhdXqeSRuvW51`)

---

## Context: Key Schema Facts

| Column | Notes |
|---|---|
| `last_login_at` | Set by the web login flow only. Telegram-only users never have this set. |
| `last_active` | Set by Telegram bot middleware on every bot interaction. |
| `onboarding_complete` | `false` for 4,661 of 4,662 users — appears never set to `true` by any code path. |
| `is_deleted` | Boolean soft-delete flag. |
| `telegram` | Telegram username handle (e.g. `@handle`). Distinct from `id` which holds the Telegram numeric ID. |
| `x_id` | X/Twitter linked account ID. |

> **Critical observation:** 4,647 of 4,662 users (99.7%) have `last_login_at IS NULL`. This is because `last_login_at` is only set by the web login flow. The overwhelming majority of PNPtv! users join and interact exclusively via the Telegram bot, which does not write `last_login_at`. `last_active` is the correct activity proxy for Telegram users. All analysis below uses `last_active` as the primary activity signal, with `last_login_at` reported for completeness.

## Category 3: Orphan Records (No FK References)

**Definition:** Users with zero rows referencing their `id` across all major activity tables: `social_posts`, `user_follows` (follower or following), `payments`, `token_purchases`, `social_post_likes`, `notifications`, `chat_messages`, `direct_messages`, `hangout_group_members`, `user_badges`, `user_security_logs`.

| Metric | Count |
|---|---|
| True orphans (zero FK references across all tables checked) | **0** |

> Every user in the database has at least one FK reference — overwhelmingly in `notifications.target_user_id` due to the hangout_call broadcast system, which fans out to all registered users. Even the 69 true-ghost accounts have 4–7 `hangout_call` notification rows each. This means the notifications system is masking the real orphan population. The actual "user-initiated activity" orphan count (excluding system-generated notifications) is **69** (see Category 1A).

## Known False Positives to Guard Against

1. **Do NOT use `last_login_at IS NULL` as a deletion criterion.** 99.7% of users have this null. It is only set by the web login flow.
2. **Do NOT use `onboarding_complete = false` as a deletion criterion.** 99.98% of users match this. The field is a dead column.
3. **Do NOT treat notification-row presence as user activity.** The `hangout_call` broadcast populates rows for all users automatically.
4. **Always exclude `id IN ('SYSTEM', 'W1Jl2z3IhdXqeSRuvW51')` from any bulk queries.**

## Queries for Future Monitoring

```sql
-- True ghost accounts (no user-initiated activity, older than 30 days)
SELECT COUNT(*) FROM users u
WHERE u.last_active < NOW() - INTERVAL '30 days'
  AND u.tier = 'free'
  AND (u.is_deleted IS NULL OR u.is_deleted = false)
  AND u.id NOT IN ('SYSTEM', 'W1Jl2z3IhdXqeSRuvW51')
  AND NOT EXISTS (SELECT 1 FROM social_posts WHERE user_id = u.id)
  AND NOT EXISTS (SELECT 1 FROM user_follows WHERE follower_id = u.id)
  AND NOT EXISTS (SELECT 1 FROM payments WHERE user_id = u.id)
  AND NOT EXISTS (SELECT 1 FROM token_purchases WHERE user_id = u.id);

-- Paid accounts with no recent activity (investigation queue)
SELECT id, username, tier, plan_id, last_active, created_at
FROM users
WHERE tier <> 'free'
  AND (last_active IS NULL OR last_active < NOW() - INTERVAL '30 days')
  AND (is_deleted IS NULL OR is_deleted = false)
ORDER BY last_active ASC NULLS FIRST;

-- No-identity web accounts (potential bot signups)
SELECT id, username, first_name, created_at, last_active
FROM users
WHERE telegram IS NULL AND x_id IS NULL AND email IS NULL
  AND (is_deleted IS NULL OR is_deleted = false)
ORDER BY created_at DESC;
```
